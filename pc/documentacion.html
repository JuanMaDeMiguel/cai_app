Brillo Adaptable: Teléfono → PC

El sensor de luz ambiente de un Android controla el brillo de una PC Linux en tiempo real, por Bluetooth.

El teléfono tiene un sensor de luz ambiente real; la mayoría de las laptops no exponen el suyo de forma usable. Este proyecto "presta" el sensor del teléfono para darle brillo adaptable a la PC: más luz → pantalla más brillante; en la oscuridad, se atenúa — todo con transiciones suaves.

Resumen

Arquitectura

[Teléfono Android]                               [Linux PC]
 Sensor de luz (lux)
   → mapeo lux→brillo % (curva log)
   → throttle (envía solo si Δ ≥ 3%)
   → Bluetooth (RFCOMM / SPP) ───────────►  bt_server.py (perfil SPP por D-Bus)
                                              → recibe "<percent>\n"
                                              → fade suave del backlight
                                              → escribe /sys/class/backlight/...

Cuatro decisiones de diseño definen el sistema:

  1. Transporte: Bluetooth Classic SPP/RFCOMM (no BLE). Es un canal tipo puerto serie, simple y robusto para teléfono↔PC.
  2. Pantalla a controlar: la pantalla interna de la laptop vía sysfs. Más confiable que ddcutil (que depende del DDC/CI del monitor y del cable).
  3. Mapeo lux→brillo: curva logarítmica recortada — ver fórmula abajo.
  4. Frecuencia de envío: enviar solo cuando el brillo calculado cambie ≥ 3%, no en cada lectura del sensor.

El "contrato" entre ambos lados

La comunicación es deliberadamente trivial: una línea de texto por mensaje, un número entero (el % de brillo) terminado en \n. Por ejemplo: "75\n".

  • UUID SPP estándar: 00001101-0000-1000-8000-00805F9B34FB
  • Trivial de generar en Java (pct + "\n") y de parsear en Python (int(float(line))).
  • Se puede depurar a ojo en la consola del server.

Lado PC (Python, carpeta pc/)

El código de la PC se separa en dos capas independientes para poder probar cada una por su cuenta:

  • Hardware (backlight.py): solo lee/escribe el brillo. No sabe nada de Bluetooth.
  • Red (bt_server.py): recibe los porcentajes por Bluetooth y llama a la capa de hardware.

2.1 · backlight.py — control físico del brillo

Es la única parte que toca el hardware. Lee y escribe el brillo a través de sysfs. Como no depende de Bluetooth, se puede probar de forma aislada.

  • _find_device(): busca el dispositivo de backlight en /sys/class/backlight/* (aquí intel_backlight) y lo cachea.
  • get_max(): lee max_brightness — el valor RAW máximo que entiende el kernel (en esta máquina, 96000).
  • get_percent(): lee el brillo actual y lo convierte a porcentaje.
  • set_percent(pct): convierte el % a RAW (pct/100 · max) y lo escribe. Cambio instantáneo. Recorta a 5–100 para no apagar la pantalla del todo.
  • fade_to(pct, ...): transición suave. Clave: interpola sobre el valor RAW (0–96000), no sobre el %, así aprovecha toda la resolución del backlight y no se ven escalones.
pc/src/backlight.pyPC · hardware
"""Control del brillo de la pantalla interna via sysfs (intel_backlight)."""
import glob
import os
import time

BACKLIGHT_DIR = None


def _find_device():
    global BACKLIGHT_DIR
    if BACKLIGHT_DIR:
        return BACKLIGHT_DIR
    devs = glob.glob("/sys/class/backlight/*")
    if not devs:
        raise RuntimeError("No se encontro ningun dispositivo en /sys/class/backlight")
    BACKLIGHT_DIR = devs[0]
    return BACKLIGHT_DIR


def get_max():
    with open(os.path.join(_find_device(), "max_brightness")) as f:
        return int(f.read().strip())


def get_percent():
    dev = _find_device()
    with open(os.path.join(dev, "brightness")) as f:
        cur = int(f.read().strip())
    return round(cur / get_max() * 100)


def _write_raw(raw):
    with open(os.path.join(_find_device(), "brightness"), "w") as f:
        f.write(str(raw))


def set_percent(pct):
    """Aplica un brillo en porcentaje (se recorta a 5..100), instantaneo."""
    pct = max(5, min(100, int(pct)))
    _write_raw(round(pct / 100 * get_max()))
    return pct


def fade_to(pct, duration=0.4, steps=60):
    """Transicion suave desde el brillo actual hasta `pct` en `duration` seg.

    Interpola sobre el valor RAW (no el %), asi aprovecha toda la resolucion
    del backlight (max ~96000) y no se ven escalones.
    """
    pct = max(5, min(100, int(pct)))
    mx = get_max()
    start = int(get_percent() / 100 * mx)
    target = round(pct / 100 * mx)
    if start == target:
        _write_raw(target)
        return pct
    dt = duration / steps
    for i in range(1, steps + 1):
        raw = round(start + (target - start) * i / steps)
        _write_raw(raw)
        time.sleep(dt)
    return pct
⚠ Permisos del backlight Escribir en /sys/.../brightness normalmente requiere root. Se resolvió con una regla udev que hace el archivo del grupo video con permiso de escritura (g+w), más agregar el usuario a ese grupo. Por eso el script cambia el brillo sin sudo.

2.2 · bt_server.py — servidor Bluetooth ★ (programa principal)

Recibe los porcentajes del teléfono y los aplica llamando a backlight.fade_to. Usa BlueZ a través de D-Bus, no PyBluez (que no compila en Python 3.14).

¿Cómo se anuncia el servicio?

  1. main() crea el bucle de eventos GLib y se conecta al System Bus de D-Bus.
  2. Instancia la clase Profile (un objeto D-Bus en PROFILE_PATH).
  3. Llama a ProfileManager1.RegisterProfile(...) con el UUID de SPP, rol server y un canal. Al registrar el perfil, BlueZ anuncia el servicio por SDP — eso es lo que permite al teléfono descubrirlo y conectarse sin hacks de canal.
  4. Arranca GLib.MainLoop() y queda esperando conexiones.

¿Qué pasa cuando el teléfono conecta?

BlueZ invoca Profile1.NewConnection(device, fd, properties) y entrega un file descriptor ya conectado. Se envuelve en un socket de Python y se lanza un hilo read_loop.

🔑 Detalle clave (bug sutil) El fd que entrega BlueZ viene en modo no-bloqueante. Hay que hacer sock.setblocking(True) o recv() falla con BlockingIOError.

read_loop() acumula bytes en un buffer y los separa por \n — porque un solo recv puede traer varios mensajes pegados o uno partido. Por cada línea parsea el entero y llama a backlight.fade_to(pct, 0.3).

pc/src/bt_server.pyPC · programa principal
"""Servidor Bluetooth SPP: recibe % de brillo del telefono y lo aplica.

Registra un perfil Serial Port (SPP) en BlueZ via D-Bus (ProfileManager1).
Asi el servicio queda anunciado por SDP y el telefono lo encuentra con
createRfcommSocketToServiceRecord(SPP_UUID), sin hacks de canal.

Cada mensaje es una linea de texto con un porcentaje entero ("75\n").

Requisitos: python3-dbus, python3-gobject.
Uso: python3 bt_server.py
"""
import os
import socket
import threading

import dbus
import dbus.mainloop.glib
import dbus.service
from gi.repository import GLib

import backlight

SPP_UUID = "00001101-0000-1000-8000-00805f9b34fb"
PROFILE_PATH = "/org/bluez/spp_brightness"
CHANNEL = 22


def read_loop(sock, addr):
    print(f"[+] Conectado: {addr}")
    buf = b""
    try:
        while True:
            data = sock.recv(1024)
            if not data:
                break
            buf += data
            while b"\n" in buf:
                line, buf = buf.split(b"\n", 1)
                line = line.strip()
                if not line:
                    continue
                try:
                    pct = int(float(line))
                except ValueError:
                    print(f"    ignorado: {line!r}")
                    continue
                applied = backlight.fade_to(pct, duration=0.3)
                print(f"    {pct:>3} -> {applied:>3}%")
    finally:
        sock.close()
        print(f"[-] Desconectado: {addr}")


class Profile(dbus.service.Object):
    @dbus.service.method("org.bluez.Profile1", in_signature="", out_signature="")
    def Release(self):
        print("Profile.Release")

    @dbus.service.method("org.bluez.Profile1", in_signature="oha{sv}",
                         out_signature="")
    def NewConnection(self, device, fd, properties):
        fd = fd.take()
        sock = socket.socket(socket.AF_BLUETOOTH, socket.SOCK_STREAM,
                             socket.BTPROTO_RFCOMM, fileno=fd)
        sock.setblocking(True)   # el fd de BlueZ viene NO-bloqueante
        threading.Thread(target=read_loop, args=(sock, str(device)),
                         daemon=True).start()

    @dbus.service.method("org.bluez.Profile1", in_signature="o",
                         out_signature="")
    def RequestDisconnection(self, device):
        print(f"RequestDisconnection: {device}")


def main():
    dbus.mainloop.glib.DBusGMainLoop(set_as_default=True)
    bus = dbus.SystemBus()
    Profile(bus, PROFILE_PATH)

    manager = dbus.Interface(
        bus.get_object("org.bluez", "/org/bluez"),
        "org.bluez.ProfileManager1")
    opts = {
        "Name": "Brillo SPP",
        "Role": "server",
        "Channel": dbus.UInt16(CHANNEL),
        "RequireAuthentication": dbus.Boolean(False),
        "RequireAuthorization": dbus.Boolean(False),
    }
    manager.RegisterProfile(PROFILE_PATH, SPP_UUID, opts)
    print(f"Perfil SPP registrado (canal {CHANNEL}). Esperando conexion del telefono...")

    loop = GLib.MainLoop()
    try:
        loop.run()
    except KeyboardInterrupt:
        print("\nSaliendo.")


if __name__ == "__main__":
    main()
⚠ Correr con el Python del sistema Se ejecuta con /usr/bin/python3 (el del sistema tiene los módulos dbus y gi); el venv del proyecto no los tiene.

2.3 · Scripts de prueba (no son parte del producto final)

Permiten validar el lado PC sin el teléfono. Todos terminan llamando a backlight.

  • apply_brightness.py: lee porcentajes de stdin (uno por línea) y los aplica. Simula exactamente lo que hace el server (recibir un % y aplicarlo), pero por tubería en vez de Bluetooth.
  • simulate.py: genera datos falsos. Modo barrido (100→5→100) o modo --lux (genera lux aleatorios y los pasa por la misma curva logarítmica que usa la app Android — sirve para mostrar que la curva está bien).
  • manual.py: prueba interactiva. Escribís un % y la pantalla hace fade. Útil para demostrar fade_to en vivo.

La curva logarítmica es el corazón del mapeo, idéntica en Python y en Java:

brillo% = clamp( log10(lux + 1) / log10(5000) · 100 , 5 , 100 )

(lux ≈ 0 oscuro, ≈ 10.000+ sol directo; 5000 como tope práctico. La escala log refleja cómo el ojo y las pantallas responden a la luz.)

pc/src/simulate.pyPC · prueba
"""Genera datos de brillo simulados para probar la PC sin el telefono.

Modo 1 (default): barrido de porcentajes 100 -> 5 -> 100.
Modo 2 (--lux): genera lux aleatorios y los pasa por la curva logaritmica
real (la misma que usara la app Android), imprimiendo el porcentaje.
"""
import math
import random
import sys
import time

DELAY = 0.03  # segundos entre valores


def lux_to_percent(lux):
    pct = math.log10(lux + 1) / math.log10(5000) * 100
    return max(5, min(100, round(pct)))


def sweep():
    seq = list(range(100, 4, -1)) + list(range(5, 101, 1))
    for pct in seq:
        print(pct, flush=True)
        time.sleep(DELAY)


def lux_mode():
    for _ in range(40):
        lux = random.choice([0, 5, 50, 200, 800, 3000, 10000])
        pct = lux_to_percent(lux)
        print(pct, flush=True)
        print(f"  lux={lux:>6} -> {pct}%", file=sys.stderr)
        time.sleep(DELAY)


if __name__ == "__main__":
    if "--lux" in sys.argv:
        lux_mode()
    else:
        sweep()

2.4 · gui/control_panel.py — panel de control (PyQt6)

Interfaz gráfica para no depender de la terminal. No reimplementa el server: lo lanza como subproceso y muestra su salida. Esto evita el choque entre el bucle de eventos de Qt y el de GLib (cada uno corre en su propio proceso).

  • find_server(): localiza bt_server.py (primero relativo al script, ya que gui/ y src/ son hermanos).
  • "Start server": lanza /usr/bin/python3 -u bt_server.py con un QProcess. Usa el Python del sistema (que tiene dbus) sin importar con qué intérprete corra la GUI.
  • on_output(): lee la salida del server línea por línea. Con una regex (-> NN%) actualiza el número grande de brillo, y detecta [+] Conectado / [-] Desconectado para el estado.
  • "Make discoverable for pairing": corre bluetoothctl para dejar la PC visible y emparejable (solo la primera vez por teléfono).
  • closeEvent(): detiene el server al cerrar la ventana.

_HERE = os.path.dirname(os.path.abspath(__file__))
SERVER_CANDIDATES = [
    os.path.normpath(os.path.join(_HERE, "..", "src", "bt_server.py")),
    os.path.join(HOME, "Documents/CAI/Android/pc/src/bt_server.py"),
    os.path.join(HOME, "Documents/CAI/pc/src/bt_server.py"),
]
SYSTEM_PYTHON = "/usr/bin/python3"
BRIGHTNESS_RE = re.compile(r"->\s*(\d+)%")

# --- arrancar el server como subproceso (evita choque Qt vs GLib) ---
def start_server(self):
    self.proc = QProcess(self)
    self.proc.setProcessChannelMode(QProcess.ProcessChannelMode.MergedChannels)
    self.proc.readyReadStandardOutput.connect(self.on_output)
    self.proc.finished.connect(self.on_finished)
    self.proc.start(SYSTEM_PYTHON, ["-u", self.server_path])
    self.set_server_running(True)

# --- parsear la salida del server para alimentar la UI ---
def on_output(self):
    text = bytes(self.proc.readAllStandardOutput()).decode(errors="replace")
    for line in text.splitlines():
        self.log.append(line)
        if "[+] Conectado" in line:
            self.connStatus.setText("📱 Phone connected")
        elif "[-] Desconectado" in line:
            self.connStatus.setText("Disconnected")
        m = BRIGHTNESS_RE.search(line)
        if m:
            self.brightness.setText(m.group(1) + " %")

# --- hacer la PC visible/emparejable via bluetoothctl ---
def make_discoverable(self):
    for args in (["discoverable-timeout", "0"],
                 ["pairable", "on"],
                 ["discoverable", "on"]):
        QProcess.execute("bluetoothctl", args)

Lado Android (Java + XML)

Manifest + UI

AndroidManifest.xml — permisos y capacidades

  • BLUETOOTH_CONNECT (Android 12 / API 31+): necesario para listar dispositivos emparejados y conectarse. Se pide en tiempo de ejecución.
  • BLUETOOTH y BLUETOOTH_ADMIN con maxSdkVersion=30: equivalentes para Android 11 y anteriores (ahí se conceden al instalar).
  • <uses-feature ... sensor.light>: declara que la app usa el sensor de luz.

res/layout/activity_main.xml — la interfaz

  • luxText: lux actuales · brightnessText: % de brillo (número grande).
  • statusText: estado de la conexión · connectButton: botón "Conectar".
  • sendSwitch: interruptor "Enviar brillo automáticamente" (deshabilitado hasta que haya conexión).

MainActivity.java — sensor + cliente Bluetooth

Es el corazón de la app. Implementa SensorEventListener.

Sensor y curva

  • onSensorChanged(event): toma event.values[0] (lux), calcula el %, actualiza la UI y, si corresponde, envía.
  • luxToPercent(lux): la misma curva logarítmica que simulate.py.
  • Throttle: solo envía si abs(pct - lastSentPct) ≥ 3. lastSentPct empieza en -100 para forzar el primer envío.

Bluetooth

  • ensurePermissionThenConnect(): valida que el Bluetooth esté encendido; si falta el permiso (Android 12+), lo pide; luego abre el selector.
  • pickDeviceAndConnect(): lista los dispositivos emparejados (getBondedDevices()) en un diálogo.
  • connect(device): crea el socket con createInsecureRfcommSocketToServiceRecord(SPP_UUID) — esto hace una búsqueda SDP del servicio SPP que publica bt_server.py y se conecta al canal correcto.
  • send(pct): escribe pct + "\n" en el OutputStream.
🧵 Modelo de hilos El sensor y la UI corren en el hilo principal. Toda la red Bluetooth (conectar, enviar) corre en un ExecutorService de un solo hilo, para no bloquear la UI. Para volver a tocar la UI desde ese hilo se usa un Handler del hilo principal (main.post(...)).

Decisiones técnicas clave

Lo que hay que saber para defender el proyecto:

DecisiónPor qué
Protocolo de texto plano ("<pct>\n")Trivial de depurar (se ve en la consola) y de generar/parsear. Alternativa binaria sería opaca.
Curva logarítmica (no lineal)La luz ambiente abarca varios órdenes de magnitud (~0 a >10000 lux); el ojo y las pantallas responden de forma logarítmica, así el mapeo se siente natural.
Throttle del 3%El sensor dispara muchísimas lecturas; enviar todas saturaría el enlace. Solo importan los cambios perceptibles.
Fade interpolando el RAWTransiciones suaves sin escalones visibles (usa toda la resolución 0–96000, no los 100 pasos del %).
SPP por SDP (D-Bus), no canal fijo por reflexiónEl canal RFCOMM fijo con la API oculta de Android era inestable ("read failed…"). Publicar el servicio y dejar que Android lo descubra por SDP es el método estándar y confiable.
Sockets BT nativos + BlueZ/D-BusPyBluez no compila en Python 3.14; la stdlib (AF_BLUETOOTH) + D-Bus cubren todo sin dependencias frágiles.
🛣 El camino recorrido (importante para entender el código) Opción A descartada: canal fijo 1 + createRfcommSocket(1) por reflexión, SIN SDP. El teléfono daba "read failed, socket might be closed or timeout"; el connect() no llegaba al server.

Opción B adoptada (funciona): registrar SPP por D-Bus → el teléfono lo descubre con createInsecureRfcommSocketToServiceRecord(SPP_UUID).

echo 'ACTION=="add", SUBSYSTEM=="backlight", RUN+="/bin/chgrp video /sys/class/backlight/%k/brightness", RUN+="/bin/chmod g+w /sys/class/backlight/%k/brightness"' | sudo tee /etc/udev/rules.d/90-backlight.rules

bluetoothctl

Estado & pendientes

✅ FUNCIONA END-TO-END

Sensor del teléfono → app → Bluetooth SPP → bt_server.py → brillo de la PC sigue la luz ambiente en tiempo real, con fade suave.

Pendiente / futuro

  • Reconexión automática si se cae el socket.
  • Foreground Service en Android: sin él, el socket se corta al minimizar la app.
  • Autostart del server en la PC con systemd --user.
  • Pulir la curva y hacer la GUI más linda.
  • Monitor externo: usar ddcutil setvcp 10 N (requiere i2c-dev y grupo i2c).

Riesgos conocidos

  • PyBluez NO sirve (Python 3.14) → se usan sockets stdlib AF_BLUETOOTH (ya resuelto).
  • Sin SDP, apps de terminal Bluetooth genéricas no descubren el servicio.
  • Android 12+: sin permisos runtime, el Bluetooth falla en silencio.
  • Background: sin Foreground Service, el socket se corta al minimizar.
